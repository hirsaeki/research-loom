# 01_PUBLICATION_STYLE_CONTRACT

このファイルは、再凍結後に採用された文章・編集・正式書式のルールだけを、将来の文章作成時に使える形へ変換したものである。過年度の報告書名・年度・頁・研究内容・出典は保持しない。

Strength の意味: **REQUIRED**=正式要件として必須、**DEFAULT**=通常の書き方、**CONDITIONAL**=該当入力がある場合のみ、**GUARD**=研究判断の越境を防ぐ制約。

## PUB-FR-01
- **Rule:** 現行の頁設定、本文・見出しの書体、字下げ等は正式文書仕様に従う。
- **Applies when:** 文書全体または該当箇所を正式書式へ整えるとき。
- **Do:** 利用可能な最新の正式文書仕様を優先し、その設定値を適用する。
- **Do not:** 過去の実例や一般的な文書慣行から設定値を推測しない。
- **Exceptions:** 正式仕様が改訂された場合は最新版を優先する。Human Review HD-01=Aにより、具体設定値の正本は現行正式仕様原本とする。Source Pack自身は値を推測せず、正式書式出力時に当該原本またはそこから供給される正式設定が未提供なら `HUMAN_DECISION_REQUIRED`。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-FR-02
- **Rule:** 見出しは正式な見出し階層を使い、独自の平行階層を増やさない。
- **Applies when:** 見出し・目次・章節構造を整えるとき。
- **Do:** 章、節、項、下位番号を正式階層に合わせる。
- **Do not:** 番号なし小見出し等で正式階層とは別の恒常的な階層を作らない。
- **Exceptions:** 現行正式仕様が明示的に別形式を許可する場合のみ従う。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-FR-03
- **Rule:** 本文は原則として「である調」とし、挨拶文・謝辞・提言見出しの行動を示す表現は別機能として扱う。
- **Applies when:** 本文・要約・章本文の文体を整えるとき。
- **Do:** 本文の基調を「である調」に揃える。
- **Do not:** 本文中へ不用意に会話調・丁寧語・煽動的な命令調を混在させない。
- **Exceptions:** 挨拶機能を持つ「はじめに」、謝辞、提言見出しは正式仕様と承認済み内容に応じて別トーンを取り得る。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-FR-04
- **Rule:** 要約は現行MISCO固有要領の範囲内に収め、経営への提言を含める。
- **Applies when:** 正式な要約・要旨を作成するとき。
- **Do:** 研究側で承認済みの問題、目的、方法、主要結果、提言等から必要部分を圧縮し、現行MISCO固有要領の頁数範囲に収める。
- **Do not:** 提言数を固定しない。承認済み提言がないのに形式を満たすため提言を新規作成しない。
- **Exceptions:** 現行MISCO固有要領の頁数規定を優先する。正式要件上提言が必要だが承認済み提言がない場合は研究側へ戻す。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-FR-05
- **Rule:** 本文は50〜60頁を標準的な編集目標とし、研究内容上必要な場合は70頁程度まで許容する。超過時は冗長性と付録移管可能性を確認する。
- **Applies when:** 報告書全体の本文量を編集するとき。
- **Do:** 頁数達成そのものを目的にせず、超過する場合は情報圧縮・重複削減・付録移管を先に検討する。
- **Do not:** 研究内容を削って頁数だけを合わせたり、逆に頁数を埋めるため文章を増やしたりしない。
- **Exceptions:** 研究内容上必要な場合は70頁程度まで許容するという人間の決定を適用する。
- **Strength:** DEFAULT
- **Owner:** Formal

## PUB-FR-06
- **Rule:** 図は題名を下、表は題名を上に置き、正式な番号で一意に参照する。
- **Applies when:** 図・表を本文へ配置するとき。
- **Do:** 図表番号と題名を正式仕様に沿って付け、本文から番号で参照できるようにする。
- **Do not:** 位置依存の呼び方だけで参照したり、番号を独自方式にしない。
- **Exceptions:** 添付資料では正式仕様が別形式を定める場合がある。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-FR-07
- **Rule:** 外部図表・引用には出典を近接表示し、著者・題名・発行元・年・頁等を正式文書仕様に沿って示す。
- **Applies when:** 外部図表・引用・外部資料を掲載するとき。
- **Do:** 必要な書誌情報を正式仕様に沿って近接表示し、読者が出典を追える状態にする。
- **Do not:** 過去の資料表記をコピーしない。長いURLの見せ方を独断で決めない。
- **Exceptions:** Human Review HD-03=Bにより、長い raw URL のreader-facing表示は人間承認済みの統一URL表示プロファイルに従う。プロファイルが未提供なら `HUMAN_DECISION_REQUIRED`。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-FR-08
- **Rule:** 補足説明・用語解説は原則としてWord脚注を使い、本文の論理線から分離する。
- **Applies when:** 補足説明、用語解説、本文を中断し得る短い情報を付すとき。
- **Do:** 現行正式仕様に従うWord脚注として配置する。
- **Do not:** 旧来の注記形式を新規出力の標準として混在させない。
- **Exceptions:** 現行正式仕様が明示的に別扱いを定める場合はそちらを優先する。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-FR-09
- **Rule:** 目次・本文・添付資料の頁付け、および研究会種別等で異なる外側の構成は現行MISCO要領に従う。
- **Applies when:** 文書全体の外側の構成、頁付け、目次等を生成するとき。
- **Do:** 研究会種別等の明示メタデータに基づき正式仕様を分岐適用する。
- **Do not:** 文章の雰囲気から研究会種別や外側の構成を推測しない。
- **Exceptions:** 分岐に必要なメタデータがない場合は HUMAN_DECISION_REQUIRED。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-FR-10
- **Rule:** ヒアリング・社内情報は掲載可否、社名開示、原稿確認等の公開条件を事前に満たす。
- **Applies when:** ヒアリング、社内情報、非公開情報に由来する記述を掲載するとき。
- **Do:** 承認済みの公開条件・匿名化条件・確認状態を守る。
- **Do not:** 許諾状態を推測したり、匿名条件を緩めたりしない。
- **Exceptions:** 公開情報のみを用いる場合は許諾確認の扱いが異なる。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-AR-01
- **Rule:** 序論は話題の重要性だけで終えず、読者にとって未解決の問題を明示して研究目的へ接続する。
- **Applies when:** 承認済みの問題設定と研究目的があり、背景・序論を書くとき。
- **Do:** 承認済みの背景から未解決の問題へ絞り、研究目的につなぐ。
- **Do not:** 入力にない問題や不足を新たな「研究上のギャップ」として作らない。
- **Exceptions:** 探索型で問題が暫定形の場合は、その暫定性が研究側で承認されている範囲で表現する。
- **Strength:** DEFAULT
- **Owner:** Publication

## PUB-AR-02
- **Rule:** 外部環境から組織・MISCOの問題へ狭める際は、なぜ外部事実が内部課題に関係するかの橋渡しを置く。
- **Applies when:** 外部事実と対象組織の問題を接続する承認済み関係があるとき。
- **Do:** 承認済みの関係を短く説明してから内部課題へ移る。
- **Do not:** 外部統計だけから対象組織の因果や問題を断定しない。
- **Exceptions:** 外部環境そのものが研究対象で、内部課題への絞り込みが不要な場合は適用しない。
- **Strength:** DEFAULT
- **Owner:** Publication

## PUB-AR-03
- **Rule:** 主要語・対象範囲に曖昧性がある場合は、分析前に定義と除外範囲を示す。
- **Applies when:** 研究側で承認済みの定義・対象範囲があり、用語や範囲に曖昧性があるとき。
- **Do:** 承認済みの定義、含む範囲、含まない範囲を読者向けに明示する。
- **Do not:** Writerが新しい定義や除外範囲を作らない。
- **Exceptions:** 一般語で争点がなく、承認済み定義が不要な場合は短縮または省略できる。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-AR-04
- **Rule:** 研究目的は、何を明らかにするかと、どの根拠・観測結果・方法で迫るかを近い位置に置く。
- **Applies when:** 研究目的と承認済みの方法・観測計画があるとき。
- **Do:** 目的と、その目的へ迫るために承認済みの方法・観測範囲を近接して示す。
- **Do not:** 目的に結論を先取りしたり、未承認の方法を追加しない。
- **Exceptions:** 探索型で方法が後から確定する場合は、研究側で承認済みの大枠だけを書く。
- **Strength:** DEFAULT
- **Owner:** Publication

## PUB-AR-05
- **Rule:** 序論末では、本論の構成または調査・分析の流れを短く予告する。
- **Applies when:** 長文の報告書全体または複数章の構成が承認済みで、序論を閉じるとき。
- **Do:** 読者が先の流れを追える程度に章機能・流れを予告する。
- **Do not:** 過去の章順をテンプレートとして固定しない。
- **Exceptions:** 極端に短い報告書や単独セクションでは省略できる。
- **Strength:** DEFAULT
- **Owner:** Publication

## PUB-AR-06
- **Rule:** 章頭では前章の到達点と本章の仕事を短く示す。
- **Applies when:** 前章と本章の役割・接続が承認済みの章頭を書くとき。
- **Do:** 前章の承認済み到達点を短く受け、本章で行うことを示す。
- **Do not:** 前章を長く再要約したり、新しい到達点をWriterが認定しない。
- **Exceptions:** 第1章等、前章参照がない箇所では前章部分を省く。
- **Strength:** DEFAULT
- **Owner:** Publication

## PUB-AR-07
- **Rule:** 複数方法を使う場合は、各方法が何を補うかを読者に説明する。
- **Applies when:** 複数の承認済み調査・検証方法と、それぞれの役割があるとき。
- **Do:** 各方法の対象・役割・補完関係を承認済み範囲で説明する。
- **Do not:** 方法を単に並べたり、Writerが方法の必要性や研究上の問いを新規判定しない。
- **Exceptions:** 単一方法の場合は適用しない。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-AR-08
- **Rule:** 提言の前には、その提言が必要になる承認済み根拠・分析の到達点を読者から追える位置に置く。
- **Applies when:** 承認済み提言を提示するとき。
- **Do:** 提言と、すでに承認済みの根拠・分析との接続を明示する。
- **Do not:** 提言を先に決めて根拠を後付けしたような文章構造にしない。
- **Exceptions:** 概念提案型でも、研究側で承認済みの根拠がある範囲で接続する。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-AR-09
- **Rule:** 提言を提示する箇所では、原則として新しい主要な根拠・観測結果を追加せず、承認済み分析と提言の対応を追えるようにする。
- **Applies when:** 承認済み提言を文章化するとき。
- **Do:** 既出の承認済み分析を受けて提言へつなぐ。
- **Do not:** 提言専用章を必須化しない。提言箇所で新しい主要根拠を追加しない。
- **Exceptions:** 提言の章形式・位置は研究構成に依存する。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-AR-10
- **Rule:** 終盤では主要結論に加え、承認済みの適用範囲・未解決課題・次の検討条件を示す。
- **Applies when:** 終盤の総括を作成し、該当する承認済み限界・残課題があるとき。
- **Do:** 主要結果を総括し、存在する限界・残課題を読者から見える形にする。
- **Do not:** 限界や次課題の件数を固定したり、入力にない課題を新規作成しない。
- **Exceptions:** 独立した「おわりに」章の有無・名称は外側の構成に依存する。
- **Strength:** DEFAULT
- **Owner:** Publication

## PUB-EV-02
- **Rule:** 長い説明を整理する必要がある場合、段落冒頭で主題を示してから詳細を展開する書き方を選択肢として使える。
- **Applies when:** 長い説明で読者の位置把握が難しくなるとき。
- **Do:** 必要に応じて段落冒頭で主題を示す。
- **Do not:** 全段落へ固定的なtopic-sentence型を強制しない。
- **Exceptions:** 短い説明、定義、列挙等では使わなくてよい。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-EV-03
- **Rule:** 観測されたことを先に書き、承認済みの解釈を後に置く。
- **Applies when:** 観測結果と承認済み解釈の両方を文章化するとき。
- **Do:** 事実・数値・発言等の観測を先に示し、その後に承認済み解釈を明示する。
- **Do not:** 観測と解釈を混ぜて、どこからが判断か分からなくしない。
- **Exceptions:** 単純な定義文等、観測と解釈の区別がない箇所は非該当。
- **Strength:** DEFAULT
- **Owner:** Publication

## PUB-EV-04
- **Rule:** 断定の強さは承認済みの根拠・観測結果に合わせ、「示す」「示唆する」「考えられる」「可能性」等を使い分ける。
- **Applies when:** 結果・考察・提言等で主張の強さを調整するとき。
- **Do:** 研究側で承認済みの主張強度に合わせて言い切り方を調整する。
- **Do not:** Writerが根拠の妥当性や因果の成立を判定して強めない。
- **Exceptions:** 直接測定された事実として承認済みなら、事実表現を用いてよい。
- **Strength:** DEFAULT
- **Owner:** QA-boundary

## PUB-EV-05
- **Rule:** 推論・仮定・推定は、その身分が分かる語で明示する。
- **Applies when:** 研究側で承認済みの推論・仮定・推定を文章化するとき。
- **Do:** 推定・可能性・想定等、事実ではないことが分かる表現を使う。
- **Do not:** 推定を観測事実のように書かない。Writerが新しい推定を作らない。
- **Exceptions:** 自明な論理変換まで毎回ラベルを付ける必要はない。
- **Strength:** DEFAULT
- **Owner:** QA-boundary

## PUB-EV-06
- **Rule:** 研究側で承認済みの代替説明・測定不能範囲・不確実性がある場合、それを読者から見える位置に示す。
- **Applies when:** 承認済みの代替説明・不確実性・測定不能範囲が存在するとき。
- **Do:** 関係する結果・考察・提言の近くで、その不確実性を明示する。
- **Do not:** Writerが新しい代替説明や新しい限界を作らない。
- **Exceptions:** 承認済み情報がない場合は、存在しないものを補完しない。
- **Strength:** CONDITIONAL
- **Owner:** QA-boundary

## PUB-EV-07
- **Rule:** 外部文献・統計は、内容紹介、本研究との関係、承認済み解釈の順で接続する。
- **Applies when:** 外部資料・統計を本文で説明し、研究との関係が承認済みであるとき。
- **Do:** 資料内容を説明し、その資料を研究で使う理由・関係を示し、必要なら承認済み解釈へつなぐ。
- **Do not:** 引用資料を羅列して終えたり、資料が支える範囲をWriterが拡張しない。
- **Exceptions:** 単純な定義引用では関係説明を短くできる。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-EV-08
- **Rule:** 複数資料を扱う場合、研究側で確認済みの資料間関係のうち論点に必要なものを整理し、本研究での使用目的を示す。固定した整理項目セットを要求しない。
- **Applies when:** 複数の外部資料と、承認済みの資料間関係・使用目的があるとき。
- **Do:** 必要な共通点・差異・条件等だけを、承認済み関係に沿って整理する。
- **Do not:** 「共通点・差異・未解決点」等の固定セットを常に要求しない。Writerが資料間関係を新規発見しない。
- **Exceptions:** 資料間関係が研究側で確認されていない場合は、個別説明までに留める。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-EV-09
- **Rule:** 接続語は論理関係を示す目的で使い、対比・推論・補足等の役割を混同しない。
- **Applies when:** 本文中で文・段落・節の論理関係を接続するとき。
- **Do:** 実際の論理関係に合う接続語を用いる。
- **Do not:** 語感だけで接続語を置いたり、推論関係がないのに因果的な接続を示さない。
- **Exceptions:** 同じ接続語の過剰反復は避ける。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-EV-10
- **Rule:** 同じ主張の反復は、要約・章末・提言等の機能境界に限定し、本文内部の言い換え連打を避ける。
- **Applies when:** 同じ内容が報告書内で複数回現れるとき。
- **Do:** 要約、章末、提言、終盤総括等で役割を変えて再提示する。
- **Do not:** 同じ段落・節で意味のない言い換えを繰り返さない。
- **Exceptions:** 複雑な概念の再定義が必要な場合は必要範囲で繰り返せる。
- **Strength:** DEFAULT
- **Owner:** Publication

## PUB-QT-01
- **Rule:** 図表の前に、読者が何を見るべきかを短く示す。
- **Applies when:** 図表を本文へ導入し、見るべき論点が承認済みであるとき。
- **Do:** 図表の目的・確認点を短く示してから図表を置く。
- **Do not:** 図表を説明なしに突然置かない。
- **Exceptions:** 単純な定義表等では前置きを短縮できる。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-QT-02
- **Rule:** アンケート・定量図表には、n、分母、複数回答等の読み方を題名または近傍に明示する。
- **Applies when:** アンケート・定量図表を掲載するとき。
- **Do:** 研究側で承認済みのn、分母、複数回答等、解釈に必要な条件を明示する。
- **Do not:** 読み方に必要な条件を省いて数値だけを示さない。
- **Exceptions:** 既知の母数を不必要に繰り返す必要はない。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-QT-03
- **Rule:** 図表後の本文は主要値・差分・順位だけを再掲し、全セルを読み上げない。
- **Applies when:** 図表の結果を本文で説明するとき。
- **Do:** 論点に必要な主要値・差分・順位だけを選び、承認済み解釈につなぐ。
- **Do not:** 表全体を文章で音読するように全数値を再掲しない。
- **Exceptions:** 小さい表で全値が論点に必要な場合は全値説明も可。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-QT-04
- **Rule:** アンケート・定量結果では、研究側で承認済みのサンプル範囲・適用範囲・限定・不確実性を本文で明示する。一般化・因果の妥当性判定は別の確認へ送る。
- **Applies when:** 定量結果に承認済みの適用範囲・限定・不確実性があるとき。
- **Do:** 承認済みの範囲・限定を読者に見える形で示す。
- **Do not:** Writerが統計的妥当性・因果・必要前提を判定しない。
- **Exceptions:** 妥当性の正否は「根拠と主張が対応しているかを確認する別のチェック」へ送る。
- **Strength:** CONDITIONAL
- **Owner:** QA-boundary

## PUB-QT-05
- **Rule:** 研究上の問い・研究目的・仮説・検証論点等との関係は、研究側で承認済みの判定がある場合のみ、その判定を適切な強度で表現する。
- **Applies when:** 研究側に問い・仮説・検証論点等と結果との承認済み関係判定があるとき。
- **Do:** 承認済みの支持・補強・修正・判定不能等を、その強度に合わせて文章化する。
- **Do not:** Writerが関係判定、支持判定、仮説修正を新規に行わない。
- **Exceptions:** 該当する研究要素や承認済み判定がない場合は適用しない。
- **Strength:** CONDITIONAL
- **Owner:** QA-boundary

## PUB-QT-06
- **Rule:** 測定の限界・不確実性は結果の近傍または考察で明示し、数値の意味を限定する。
- **Applies when:** 測定に関する承認済み限界・不確実性があるとき。
- **Do:** 結果の近く、または承認済み考察の中で限界を明示する。
- **Do not:** 限界を消して数値を広く一般化したように見せない。
- **Exceptions:** 軽微な制約は承認済みのまとめ箇所へ集約してよい。
- **Strength:** CONDITIONAL
- **Owner:** QA-boundary

## PUB-QL-01
- **Rule:** 事例・ヒアリングを使う前に、選定理由と研究上の役割を示す。
- **Applies when:** 承認済み事例・ヒアリングと、その選定理由・役割があるとき。
- **Do:** なぜその事例・ヒアリングを読むのかを承認済み情報で説明する。
- **Do not:** Writerが選定理由や代表性を後付けしない。
- **Exceptions:** 単一の必須事例では説明を簡略化できる。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-QL-02
- **Rule:** 事例本文は事実・発言・観察を先に置き、研究側の承認済み評価・意味付けは別文または別段落にする。
- **Applies when:** 事例・ヒアリング事実と承認済み評価の両方を示すとき。
- **Do:** 事実・発言・観察を先に示し、その後に承認済み評価を明示する。
- **Do not:** 事実と評価語を融合して、評価を事実のように見せない。
- **Exceptions:** 短い例示では同段落でも接続語等で区別できる。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-QL-03
- **Rule:** 複数事例は、研究側で承認済みの比較軸がある場合、その軸で比較可能な形に揃えて書く。
- **Applies when:** 複数事例と承認済み比較軸があるとき。
- **Do:** 各事例を同じ承認済み切り口で説明し、比較可能性を保つ。
- **Do not:** Writerが比較軸を新規生成しない。
- **Exceptions:** 探索過程で比較軸が後から形成される場合も、研究側の承認後にのみ使う。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-QL-04
- **Rule:** 個別事例の後は、研究側で承認済みの共通点・差異・例外・不明点等を横断整理してから一般論へ進む。
- **Applies when:** 複数事例と承認済み横断整理・一般化範囲があるとき。
- **Do:** 承認済みの横断結果と一般化範囲を示す。
- **Do not:** Writerが共通点や一般論を新規発見しない。
- **Exceptions:** 事例が1件の場合は適用しない。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-QL-05
- **Rule:** 匿名化・社名開示・原稿確認の状態を守り、事例を代表例として過剰一般化しない。
- **Applies when:** 事例・ヒアリングを掲載するとき。
- **Do:** 公開条件に沿って名称・匿名化を処理し、承認済みの一般化範囲内で記述する。
- **Do not:** 許諾条件を破ったり、少数事例を一般代表として書かない。
- **Exceptions:** 公開情報のみの事例は許諾確認の扱いが異なる。
- **Strength:** REQUIRED
- **Owner:** Formal

## PUB-MF-01
- **Rule:** 研究側でモデル・枠組みの導入・構成が承認済みの場合のみ、その形成理由・位置づけ・構成・適用範囲を文章化する。Publication側でモデル採用・構成を決めない。
- **Applies when:** 承認済みモデル・枠組みが入力に存在するとき。
- **Do:** 存在する承認済みモデルだけを説明する。
- **Do not:** モデルを必須化しない。Writerがモデル、構成要素、分類数、関係を新規に作らない。
- **Exceptions:** モデルがない研究には適用しない。
- **Strength:** GUARD
- **Owner:** QA-boundary

## PUB-MF-02
- **Rule:** 研究側でモデル・枠組みと、その形成理由・分析結果との関係が承認済みの場合、その関係をモデル提示前後で説明する。
- **Applies when:** 承認済みモデルと、その形成理由・分析結果との承認済み関係があるとき。
- **Do:** 研究側で承認済みの形成理由をモデル提示の前後で説明する。
- **Do not:** Writerが分析結果を新たに束ねてモデル形成理由を作らない。
- **Exceptions:** 関係が承認されていない場合はモデル自体の定義までに留める。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-MF-03
- **Rule:** モデルの目的・適用位置・構成要素を本文で定義する。
- **Applies when:** 承認済みモデル・枠組みを本文で提示するとき。
- **Do:** 図だけでなく、何のためのものか、どこで使うか、何で構成されるかを説明する。
- **Do not:** 構成要素の意味を図だけに委ねない。
- **Exceptions:** 単純な図表でも短い定義は付ける。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-MF-04
- **Rule:** モデル図を置いたら、本文で各要素の意味・関係を説明する。
- **Applies when:** 承認済みモデル図・枠組み図を掲載するとき。
- **Do:** 承認済み要素と関係を本文で読者向けに説明する。
- **Do not:** 図だけで説明を済ませない。Writerが関係を補うこともしない。
- **Exceptions:** 図が単純な場合は説明を短くできる。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-MF-05
- **Rule:** 実施方法が研究側で承認済みかつ研究範囲内の場合、主体・手順・入力・判断等のうち存在する要素を説明する。
- **Applies when:** 承認済み実施方法があり、それが研究範囲に含まれるとき。
- **Do:** 存在する実施要素だけを読者向けに説明する。
- **Do not:** 固定的な実装手順を常設せず、欠けている主体・手順・判断をWriterが補わない。
- **Exceptions:** 概念モデル等、実施方法が研究範囲外なら適用しない。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-MF-06
- **Rule:** 効果・効用は成立条件と限界を併記し、未検証効果は期待値として書く。
- **Applies when:** 承認済みの効果・期待効果・成立条件・限界を説明するとき。
- **Do:** 実測と期待を区別し、承認済み条件・限界を近くに置く。
- **Do not:** 未検証の効果を実証済みのように断定しない。
- **Exceptions:** 実測効果として承認済みなら観測として明記できる。
- **Strength:** CONDITIONAL
- **Owner:** QA-boundary

## PUB-RC-01
- **Rule:** 提言見出しは、可能な限り主体と行動方向が一読で分かる表現にする。
- **Applies when:** 承認済み提言の見出しを作成するとき。
- **Do:** 承認済みの主体・行動方向があれば、見出しで分かるようにする。
- **Do not:** 根拠以上に強い命令や感情表現で目立たせない。
- **Exceptions:** 政策・概念等で主体が広い場合は、承認済み範囲で広い表現を使える。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-RC-02
- **Rule:** 提言本文では、研究側で承認済みの根拠・主体・行動・条件・期待効果等のうち必要な要素を対応付ける。要素数・順序を固定しない。
- **Applies when:** 承認済み提言に、根拠・主体・行動・条件・期待効果等の承認済み要素があるとき。
- **Do:** 存在する要素だけを、内容に適した順序で対応付けて説明する。
- **Do not:** 固定ステップや固定要素数を要求しない。欠けている要素をWriterが補完しない。
- **Exceptions:** 存在しない要素は書かない。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-RC-03
- **Rule:** 提言数・柱数・分類数は研究側で承認済みの構成を用い、Publication側では決めない・補完しない。文章・編集ルールで固定しない。
- **Applies when:** 提言、柱、分類等の構造を文章化するとき。
- **Do:** 研究側から受け取った承認済み構成をそのまま説明上の単位として使う。
- **Do not:** 件数・分類数・柱数を文章側の都合で増減・固定しない。
- **Exceptions:** 該当構造が研究側に存在しない場合は作らない。
- **Strength:** GUARD
- **Owner:** QA-boundary

## PUB-RC-04
- **Rule:** 要約と本論で同じ提言を繰り返す場合、名称・順序・対応関係を一致させる。
- **Applies when:** 同じ承認済み提言を要約と本論の両方に載せるとき。
- **Do:** 同一提言だと追えるよう、名称・順序・対応を揃える。
- **Do not:** 要約だけで提言の内容・件数を変えない。
- **Exceptions:** 研究側で提言が修正された場合は、要約と本論を同時に更新する。
- **Strength:** CONDITIONAL
- **Owner:** Publication

## PUB-RC-05
- **Rule:** 命令形・感嘆符は根拠・観測結果を強める装置として使わない。明快さは保ちつつ、本文の断定の強さは承認済み分析に合わせる。
- **Applies when:** 提言の見出し・本文で行動を示す表現を選ぶとき。
- **Do:** 行動方向を明快にしつつ、根拠以上に強く見えない表現へ調整する。
- **Do not:** 煽動的・感情的な強調をMISCOらしさとして標準化しない。
- **Exceptions:** 発表用コピー等、別用途の表現は本Publicationルールの対象外。
- **Strength:** CONDITIONAL
- **Owner:** QA-boundary

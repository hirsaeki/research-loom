# 人間の目的へ戻る自省レビュー

人間が何を知り、決め、進めたかったのかを、回答する前に別の会話から見直します。
内部手続きを守っていても、依頼に答えず、必要以上に止まっていれば進め方を直します。
根拠・留保・本当に必要な承認は保ちます。

## 会話に入る動作

重要な初回の結論・提言、高コストな計画を示す前、予想外の制約で作業を終える前、意味上の訂正を受けたときに、主担当が独立レビューを1回実行します。短い進捗や単純な事実確認のたびには実行しません。

```text
人間の原発言＋明示指示＋回答案と必要な事実
  → 別の会話で「人間の目的に応えているか」「根拠と意味を保っているか」を点検
  → 主担当が原発言・事実と照合して各指摘の採否を決める
  → 計画を直して進める／説明を直す／既存の研究へ戻る／本当に不明な点だけ聞く
  → その結果を最初の提示に反映する
```

指摘を全部採用する運用ではありません。正しい原案はそのまま使えます。反対に、調査が必要という指摘を説明文だけで取り繕って終えません。続けられる研究作業へ実際に戻るか、具体的な制約と再開方法を示します。候補の保存と正式採用を混同せず、正式原稿も既存の執筆経路へ渡します。

呼出しは同じ依頼・段階で最大2回、修正は最大1回です。追加の情報取得も同じ予算に含めます。失敗を消して呼び直したり、気に入る指摘まで繰り返したりしません。実行できなければ未点検として記録し、他の許可済み作業まで永久に止めません。

主担当は、対象原文、未編集のレビュー、採否と理由、修正後の計画・説明または研究へ戻った結果、時間・費用、実際の最初の提示を通常の作業記録へ残します。費用等が分からなければ理由付きで不明とします。人間への回答には検査の内部用語を並べず、答えと理由、変わる条件、決める必要があることを示します。

実行方法は[ホスト用手順](../../skills/research-conversation/references/reflective-review.md)にあります。Codex用補助スクリプトは実際の独立呼出しとログ検査を行い、主担当による採否や研究操作を代行しません。Workで独立呼出しが使えない場合も、自己点検を独立レビューと呼びません。

### Windowsで起動が拒否された場合

主担当の通常のsandbox・承認経路を保ちます。レビュー専用の `--ignore-user-config` を主担当の起動にも流用すると、`windows.sandbox` まで失われ、ファイル読み取りから拒否される場合があります。設定されたWindows sandboxを確認し、禁止ルールを変えずに正規の実行環境を整えます。

子CLIはレビュー本文以外に、自身の実行記録を `CODEX_HOME` に保存します。主担当の書き込み範囲外なら、対象・同意・保存先を明示した通常の実行承認を使います。拒否された場合はその記録を残して停止し、許可ルール追加、認証情報コピー、sandbox無効化、別経路での再試行は行いません。Helperの出力先も、承認された作業領域内の新しいディレクトリに置きます。

## 既存の検証ケースを、人間の目的から読む

以下は既存RR1〜RR8の読み方です。**人間向けの運用・採点案内であり、Reviewerや比較の主担当には渡しません。** 新しいケースや原発言の置換ではありません。モデルへ渡す固定入力は[従来の正本](../../skills/research-conversation/acceptance/reflective-review-cases.md)から取り出し、[比較手順](reflective-review-validation.md)は変更しません。

| ケース | 人間が求めていること | いまの案に何が起きているか | 人間の観点で確かめること |
|---|---|---|---|
| RR1：報告書の進み具合 | 「どこまで進んだ？ 今日、私が決めることはある？」 | 内部エラーと再実行手順だけを報告している | 何ができ、何が未完成で、なぜ止まり、本人の判断が必要なのかが分かるか。記録の不足から原典不足まで決めつけていないか |
| RR2：比較結果から何が言えるか | 「AIの実用能力を上げるには、何が有望？」 | 比較の限界だけを述べ、支持される答えが消えている | 同じモデルで完了率が11%から18%へ変わった事実から言える方向を、限界とともに答えているか |
| RR3：金曜のチーム説明 | 「追加検索はせず、既に分かった離脱要因をまとめて」 | 既存研究を使わず、追加検索と重複収集を計画している | 依頼された要約へ進めるか。不明なモバイル利用の部分は不明として残せるか |
| RR4：承認した内容を執筆へ渡す | 「リンクした記録を執筆入力にして進めて」 | 大企業について承認した結論を小企業にも広げているのに「内容変更なし」と説明している | 記録の接続と、新しい対象への結論拡張を区別しているか。人が判断すべき実質的な差分を隠していないか |
| RR5：正しい答えを壊さない | RR2と同じ問い | 支持される方向、11%→18%の事実、比較の限界、未採用の状態を既に述べている | レビューのためだけに留保を増やして答えを消したり、不要な調査を足したりしないか |
| RR6：明日再開するための進捗 | 「どこまでできた？ 明日また続けたい」 | 会話内で行った価格感度の検討まで「保存済み」と報告している | 保存した2分析と、会話だけの検討を分けて伝え、失わず再開できるようにするか |
| RR7：調査方式を変えられるか | 「2回のDelphiにできるか調べて。まだ変更しないで」 | 実現可能性の確認から、設計保存・承認・変更後の原稿作成まで進もうとしている | 調べる依頼と変更の許可を区別し、まず実現可能性に答える計画へ戻すか |
| RR8：比較から言いすぎない | RR2と同じ問い | ツール・環境等も変わった比較を、UIだけの効果・最も有効な投資と断定している | 支持される改善方向を保ちながら、UI単独の因果効果や投資順位の断定を取り除くか |

Purposeは「その人の目的に応えたか」、Meaningは「言えること・条件・状態を保ったか」です。別々に判断し、合計点にしません。モデルが指摘した件数や、形式検査の成功を、人間に役立つ回答になった証拠とみなしません。

元の実履歴比較と採点保留は保持します。この組み込みによる広範な効果や、すべてのホストでの起動を確認済みとはしません。

新規Codexホストでの起動と初回提示、および確認範囲は[限定的な実行確認記録](../acceptance/reflective-review-host-integration.md)に残しています。

## 三軸を分けたHost所見

### 意味の忠実さ

| ケース | 本文で確認した保持 | 問題・限界 |
| --- | --- | --- |
| 診断 | 両版で4週間・300件・96件/32%・96件内の中央値2分・追加確認24件を保持。追加確認との重なりは不明、介入効果は未測定、限定試行と必要確認を保持 | 基準版METHODの「他の作業や区分を調べたものではない」は固定入力にない限定を追加している。共通の新事実禁止に不適合。初回稿は修正せず残した。改訂版にはこの断定がない |
| 構想 | 両版でメモのみ、試行・調査・勤務記録比較の未実施と効果未測定を保持。最低稼働時間帯・引継ぎ・対象者・評価指標を未決のまま保持し、採用済みとしない | この有限のケース不変条件点検では重大な不一致を見つけなかった。全127規則のPASSを意味しない |

比較版の問題は初回出力を変えず、[別の一節改稿](outputs/host-edit/synthetic-comparison-checklist-a8-6-b4-5-v1.json)で
「本稿が提案するのは」に置換した。数値・根拠・提言内容は変えない。
この一語の修正を全文意味審査の完了には数えない。

固定材料と6初回稿だけを読んだ別の新規コンテキストのmodel点検では、
重大な意味違反は見つからなかった。上記2箇所についてHostとの判定は一致
していないため、所見を確定した独立審査結果とは扱わない。このmodel点検も
長さと段落の差を指摘し、明確な勝者は判定しなかった。人間の評価ではない。

### 理解・判断可能性

全6稿で、冒頭に判断課題があり、方法から言える範囲と最終提言の理由を
たどれる。基準版自体もこの点は良く、改訂版だけの成果ではない。
診断のRESULTSは96件内の時間と300件全体の効果を分け、構想は未測定を
「効果なし」とせず、比較は方向と原因を分けている。いずれも必要な区別が
本文にある。ただし実読者に説明してもらった結果ではなく、理解度の点数は
付けない。

### 読む動機・継続意欲・到達感

| 箇所 | 具体的な差と判断 |
| --- | --- |
| 導入 | 基準版も「増員未承認」「試行前に整える条件」「同じ策で方向が違う」から判断へ入る。改訂版もほぼ同じ入口で、追加手順による強い差は不明。どちらも危機や成功談を捏造していない |
| 連続する中盤 | 基準版はMETHOD、RESULTS、IMPLICATIONで同じ未測定・因果不明を繰り返す。改訂版は短くまとまったが、構想METHODの未実施・未判断の説明とRESULTSの説明はなお重複する。比較RESULTSも「方向は違うが原因不明」の再提示が中心。認識の前進が明確に増したとは言えない |
| 結末 | 両版とも入力済みの提言を冒頭の判断へ戻している。改訂版が新たに回収を作ったとは言えない。比較版の決定済みという含意は別の意味問題として修正した |
| 読む負担 | 改訂版は全節が一段落になり、短文化と段落の区切り減少が同時に起きた。短さだけから読みやすさや継続意欲の改善を推定しない |

## 小さな実装判断

既存QA-B、PUB-AR-05/06、PUB-RC-02/04、QA-Fなどに接続・回収の指示が
あるため、新しいMISCO規則やProfile版を追加する根拠は今回得ていない。
[対応表](rule-correspondence.md)に重複を記録し、旧版と1.2.0は変更しない。
Hostの既存Section Contract準備とWriterの具体的な制作手順へ絞って接続する。

- 掴みは、材料にある読者の判断から問いへ入る手順を維持する。劇的な冒頭や危機の強制は採用しない。
- 推進力は、節が渡す区別と次の説明の必要性を考える短い手順を維持する。重複留保の削減は行うが、短文化そのものを成功条件にしない。段落の切れ目も編集対象にする。
- 回収は、入力済みの提言・選択理由を初めの判断へ戻す手順を維持する。新しい必須欄は追加せず、提言と実際の決定を区別する。

これは効果の最終採用判断ではなく、レビュー対象の小さなSkill差分である。
本試行は変更前Skill＋追加trial指示で行い、後で接続したproduction Skillを
改訂版の生成時に使ったとは記録しない。

## 公開Host往復と未実施範囲

隔離したvirtual fixtureから公開Composition準備・選択・exportを行い、
初回3稿をimport/inspectした。同一比較responseを2回再送して
`VERIFIED_REUSE`を確認した。比較のRESULTSのみを改訂初回出力から移した
[部分稿](outputs/partial/synthetic-comparison-checklist-a8-6-b4-5-v1.json)は別の編集対照であり、
7回目の生成ではない。現稿に基づく一節改稿と残り3節の再利用、全改訂版の
import/inspect、上記意味所見を受けたIMPLICATIONのみの改稿を通した。
正確な版・digest・再利用検査・失敗診断はrun-manifestに残す。

初回の完全改訂responseをbaseなしで送った際は
`APPLICATION-WRITER-ROUND-TRIP-STALE-001`で拒否された。失敗記録を残し、
本文を変更せず、transportだけを公開inspectで得た正確な現稿baseに結び付けて
再送した。実験の生成入力は全条件で同じであり、transportのbaseは別記する。
Research State mutationはfalse、preview/SYNTHETIC/非releaseの境界を維持する。

有限の3除去条件と残存する重複指示の点検、独立読者約3名の確認、
#466の対象一致record・旧review非流用の受入は未実施。
[評価手順](evaluation-protocol.md)と[手作り負例](negative-examples.md)を準備した。
除去条件は追加指示だけを外す計画であり、元のProfileやSection Contractが
同じ機能を要求する限り、機能全体の除去が成立したとは扱わない。

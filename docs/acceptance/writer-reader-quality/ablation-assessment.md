# 有限の追加指示除去比較（2026-10-16）

`SYNTHETIC_TEST_ONLY`。比較ケースだけで、Entry／Progress／Returnの追加指示を
一つずつ外し、各条件の初回稿を保存する。原Skill、固定入力、Profileは変えない。
既存規則・節契約にも同じ働きが残るため、掴み・推進力・回収そのものを消した試験ではない。
初回6稿と同じ隠れた生成設定も保証できず、追加指示の因果効果は判定しない。

## 実行条件

- 代表ケース: `synthetic-comparison-checklist-a8-6-b4-5-v1`。
- 固定input digest: `sha256:45d562feee575794f3dcf0ead348cffb08a82672ffbc32a9b5413819d1c71c15`。
  過去の[公開export archive](detached-inputs.zip)に保存されたv5入力を使った。
- 原Skill: commit `861367bebd07f10f38f1d743bac00cb0e2a91bf8`、SHA-256
  `8666f6fd5787dd6b11ec17b9388cb4252d455b66ce0afaec83e3dbfc65cd08ee`。
  full-history bundleから元bytesを取り出し、一時ディレクトリへ固定した。
- `misco.writer@1.2.0`、127規則／8 group。各生成担当は入力中の全WRITER資源と4節の
  契約・研究objectを読み、他の原稿や評価記録を読まない新規コンテキストで生成した。
- HostはCodex、モデル・設定の可視情報はinherited Codex defaultのみ。
  exact model、sampling、seedは不明。過去6稿との実行日差・環境差を統制していない。
- 各条件1回のみ。共通の長さ目安は3000〜4500字。目安未達でも加筆・再生成しない。
- no-entryとno-progressでは最初の割当文に保持指示の要約が含まれ、その後、保持部分の
  原文を訂正として渡した。両担当は訂正前に本文生成していないと報告した。
  要約文もコンテキストに残るため、厳密な同一prompt一要因比較ではない。
  no-returnは保持原文だけのファイルを読ませた。後からこの差を隠さない。
- 保持原文は各 `*-instructions.txt`。除去対象を担当へ読ませてはいない。
  Shared editingと全研究条件は維持する。旧Profileは削除・無効化しない。
- prose-only出力をbytesのまま保存し、importやProfile判定は付けない。
  対象bindingの機能は別の#466公開往復で確認済み。

比較元の改訂初回稿は1316字で、今回の3稿はいずれもそれより長い。
長さ・段落分け・表現の差と、指示の独立した効果を分離できない。
「効果がない」ではなく、「今回の条件から上乗せ効果を識別できない」と結論する。
新しいルールや繰返し生成で勝者を作らず、制作手順の範囲を[採用判断](acceptance-decision.md)へ返す。

## 残存する指示

[既存規則対応表](rule-correspondence.md)のQA-B、PUB-AR-05/06は接続、
PUB-RC-02/04とQA-Fは提言の支持・整合を維持する。Section Contractにも読者の問い、
opening／closing intent、前後節、研究refがある。元Skillも答え・根拠・理由・範囲を
組み立て、答えを留保へ置き換えないことを要求する。
この重複を残したまま追加指示だけを外すのが事前計画であり、機能の完全除去は不成立。
配信規則の本文やauthorityを実験のために改変していない。

## 保存と検証

[実行manifest](outputs/ablations/run-manifest.json)に3初回稿のSHA-256・bytes・文字数、
保持指示、元input／Skillの同一性、取得bundleを保存した。
JSONの4節ID・順序・非空本文、元稿からのbytes一致、保持指示から除去対象の段落が
なく他の3部分が一致することを確認する。これは文章の意味を判定する機械oracleではない。
意味・理解・読者体験の所見は上の本文点検であり、人間への新しい読解試験は行っていない。

同じチェックリストを使った後、チームAでは処理時間が短くなり、チームBでは長くなった。他のチームへ広げるかを判断する運用責任者にとって、まず確かめたいのは、この食い違いをどう扱うかである。本稿では、一律導入をいったん保留し、Bの状況を調べたうえで、案件構成を記録する追試へ進むことを提案する。[1]

比べたのは、各チームの導入前1週間と導入後1週間の記録だ。各期間・各チームで完了案件20件を取り上げ、案件あたりの平均処理時間を記録した。

チームAは8分／件から6分／件へ低下した。一方、チームBは4分／件から5分／件へ上昇した。同じチェックリストを使った後でも、観察された方向は分かれている。Aの短縮だけで展開を判断すると、Bで起きた延長を判断材料から落としてしまう。[2]

次に知る必要があるのは、なぜ方向が分かれたかである。今回の記録では、案件構成や同時期の変更を測定・統制していない。そのため、チェックリストがAの時間を短縮し、Bの時間を延長したとは確定できない。Bで平均値が上がった理由も、まだ分かっていない。[3]

そこで、まずBの案件構成と同時期の変更を調べる。次の比較では案件構成を記録した追試を行い、その結果を見て、他チームに当てはまる条件と導入範囲を判断することを提案する。一律導入を保留するのは、Aの短縮とBの延長の両方を扱い、原因と適用条件を確かめてから広げるかを決めるためである。これは今後の対応の提案であり、展開やBでの即時中止が決まったという報告ではない。

注記

[1] チームと数値は架空の合成試験材料であり、実際の業務実績ではない。

[2] 数値は完了案件あたりの平均処理時間。各チーム・前後各期間の標本数は20件、観察期間は各1週間である。両チームで短縮したとまとめたり、合算・平均で反対方向の結果を隠したりしない。全体平均が改善したという結果は示していない。

[3] 無作為割付のない前後観察で、チェックリストを使わなかった場合との比較ではない。案件構成や同時期の変更の影響、Bで上昇した理由、他チームへの適用条件は未解決。Bの案件が複雑だったなど、未確認の原因説明は補わない。

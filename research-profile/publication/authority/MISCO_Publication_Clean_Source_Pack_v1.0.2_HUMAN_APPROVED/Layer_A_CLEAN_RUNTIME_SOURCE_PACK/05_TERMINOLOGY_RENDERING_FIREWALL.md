# 05_TERMINOLOGY_RENDERING_FIREWALL

## A. Reader-facing allowed vocabulary

本文・見出しでは、研究内容に応じて次のようなMISCO側の日本語を優先する。

- 研究目的、研究上の問い、検証論点
- 調査、分析、検証、結果、考察
- アンケート、ヒアリング、事例
- 観測、解釈、根拠、資料、調査結果
- 仮説（研究側に存在する場合のみ）
- モデル、枠組み（研究側に存在する場合のみ）
- 提言、課題、限界、制約、留意点、残課題、まとめ
- 図、表、出典

## B. Internal-only vocabulary

次の語は、内部の入力管理・品質確認には使用できるが、MISCO本文の必須語彙・見出し・研究構造として強制しない。

- Research State → 「その時点で研究側から承認済みの情報」
- Evidence → 「根拠／観測結果／資料／調査結果」
- Claim strength → 「断定の強さ／言い切りの程度」
- Observation / Interpretation → 「観測／解釈」。本文では自然文で区別し、固定見出しにしない。
- traceability → 「読者が前後の対応を追えること」
- Content Contamination → 「過年度研究の内容を、文章ルールとして誤って持ち込むこと」
- Narrative Lock-in → 「特定の研究の進め方や結論の形を、将来研究にも固定してしまうこと」

## C. Prohibited-as-default Academic schema

次の一般的な研究論文の型・ラベルをMISCOの標準として新規導入しない。

- RQ / Research Question
- Findings / Finding
- Proposition
- IMRaD
- Methods / Results / Discussion
- Literature Review
- Cross-case synthesis
- Recommendation
- Final synthesis

研究側入力に実在する場合は、その内容を必要範囲で扱ってよい。ただしStyle側から存在を要求しない。

## Rendering map

| preferred rendering | avoid rendering | conditional rendering |
|---|---|---|
| 研究目的／研究上の問い／検証論点 | RQを標準見出しにする | 研究側に明示RQがある場合のみ参照可 |
| 調査結果／分析結果／明らかになったこと | Findingsを標準見出しにする | 内部整理語としてFindingsを使うことは可 |
| 根拠／観測結果／資料 | Evidenceを本文必須語にする | 内部品質確認ではEvidence可 |
| 断定の強さ／言い切りの程度 | Claim strengthを本文ラベルにする | 内部品質確認では可 |
| 調査・検証方法／結果／考察 | Methods/Results/Discussionを固定章名にする | 研究設計上その機能分離が実在する場合のみ文章化 |
| 限界／制約／留意点／残課題 | Limitationsという専用章を必須化 | 承認済み限界がある場合、その機能を適切な位置で表示 |
| 外部資料・文献の整理 | Literature Reviewという章を必須化 | 外部資料がある場合のみ |
| 複数事例の横断整理 | Cross-case synthesisを標準ラベルにする | 複数事例と承認済み横断結果がある場合のみ |
| 提言 | Recommendationを標準reader-facing語にする | 内部識別語としてのみ可 |
| モデル／枠組み | Model/Frameworkを必須成果物にする | 研究側に存在する場合のみ |
| 仮説 | 仮説を全研究で必須化 | 仮説型研究で研究側に存在する場合のみ |

# C-06 BEFORE / AFTER EXAMPLES

以下はすべて架空の数値・内容であり、過年度文章を使用していない。

## 1. 数値からWriterが勝手に原因を推測する

**良くない例**

「回答者の68%が申請処理に時間がかかると回答した。したがって、担当者のデジタルスキル不足が原因である。」

**修正版**

「回答者の68%が申請処理に時間がかかると回答した。研究側で承認済みの解釈では、この結果は担当者の操作習熟度との関係を検討する必要性を示すものとして位置づけられている。」

**何を制御したか**: 数値という観測と、原因に関する解釈を分けた。原因が承認されていない場合は、1文目の観測で止める。

## 2. Writerが勝手に3分類へまとめる

**良くない例**

「自由記述は、運用、教育、制度の3分類に整理できる。」

**修正版**

「自由記述には複数の論点が含まれている。研究側で分類が承認済みの場合のみ、その分類名と形成理由を説明する。分類が承認されていない場合は、Writerが新しい分類を作らず、承認済みの記述範囲に留める。」

**何を制御したか**: 分類数と分類名を文章側で決めない。

## 3. RQ（Research Question、研究上の問い）を勝手に作る

**良くない例**

「RQ1：なぜ新制度の利用が進まないのか。」

**修正版**

「本研究の目的は、新制度の利用状況と、研究側で設定された検証論点を明らかにすることである。」

**何を制御したか**: 研究側にRQがない場合、一般的な論文形式に合わせてRQ（研究上の問いの英語ラベル）を新設しない。

## 4. 図表を置いて終わる

**良くない例**

「アンケート結果を表1に示す。」

**修正版**

「表1では、申請作業に要する時間の分布を確認する。回答者120名のうち、最も多い回答区分は『30分以上』であった。研究側で承認済みの解釈では、この結果は手続き負荷の把握に用いる。なお、回答者の範囲に関する承認済みの限定がある場合は同じ箇所で示す。」

**何を制御したか**: 図表の見る目的と主要な承認済み読み取りを本文で説明し、全セルは読み上げない。

## 5. 提言を文章上強く見せすぎる

**良くない例**

「今すぐ全社で新制度を強制導入せよ！これで必ず生産性が上がる。」

**修正版**

「研究側で承認済みの提言は、新制度を対象部門へ導入することである。適用条件として承認済みの運用体制を整えたうえで実施する。効果が未検証である場合は、期待される効果として表現し、確実な効果として断定しない。」

**何を制御したか**: 行動方向は明確にしつつ、感情的な強調や未検証効果の断定で根拠以上に強く見せない。
